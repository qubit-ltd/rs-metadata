## 方案选择

采用最小方案：版本依赖代替四个外部路径依赖；在现有公开集成测试中增加两个错误优先级回归。无需改变架构、生产逻辑、公开 API、V1 wire 格式、Rust 1.94 最低版本或依赖 feature。

不采用补齐兄弟仓库 CI checkout：它增加环境耦合，且需要处理受管清单，不满足独立检出目标。不采用新建内部测试钩子、公开 seed 或大规模 4096/4097 项测试：公开入口和限额为 1 的负载即可验证目标合同。

## RSMD-001：依赖来源与隔离验证

Cargo.toml 改为以下四条，其他声明保持原契约：

```toml
qubit-datatype = { version = "^0.15", default-features = false, features = ["converter"] }
qubit-json = { version = "^0.12", optional = true }
qubit-redact = { version = "^0.10", default-features = false }
qubit-value = { version = "^0.13", default-features = false, features = ["converter", "redact"] }
```

使用 Cargo 正常解析同步根 Cargo.lock 与 fuzz/Cargo.lock，仅接受来源、checksum 和依赖解算必需的变化，不做无差别 cargo update。fuzz/Cargo.toml 的 path = ".." 是仓库内部关系，保留。

先核实已发布版本及所需 feature。若注册表版本与本地候选代码不兼容，保留具体差异和错误，不能自动升级版本范围、修改兄弟仓库、发布依赖或用 patch 掩盖结果。此时再提出限于本条目的替代方案。

实施时在当前 workspace 内创建仓库外的专用验收快照目录，不注册新 Paseo workspace。复制当前工作树的构建输入，包括暂存后仍存在于工作树的改动；排除 .git、target、缓存和本地 .cargo/config*，不复制兄弟源码目录。使用 git ls-files 与非忽略 untracked 清单确定输入，不修改原树。检查父目录没有四个兄弟仓库，并检查实际 Cargo 配置没有 path patch、source 替换或依赖注入；需要时隔离 Cargo 配置环境，不能读取并输出凭据。

修复前保存缺失兄弟路径的解析失败；修复后用最终文件重新制作相同隔离条件的快照。在其中分别执行根和 fuzz manifest 的 cargo metadata --locked，确认四个包均来自注册表；最后执行一次既有 CI。隔离副本只是验收产物，非新 workspace，不以 HEAD 或提交作为解锁条件。

## RSMD-002：领域值解码前拒绝超量条目

测试落在 tests/metadata_wire_limits_tests.rs，通过现有公共 Metadata::decode_json_slice_with_limits 和 MetadataSchema::decode_json_slice_with_limits 观察行为，不扩大生产可见性。

两条测试都执行三步：

1. 只有一个合法条目时，在领域限额为 1 的配置下成功，确认等值边界和输入基线有效。
2. 添加排序靠后的第二个 key，值为 JSON null。null 是合法 JSON，但不是合法 Value V1 payload 或 MetadataField。限额仍为 1，必须得到 Domain(WireLimitExceeded { kind: Entries, value: 2, maximum: 1 })。
3. 将领域限额提高为 2，同一负载必须失败，且不能再返回条目超限，以证明第二项确实触发领域解码错误，而非无效测试数据或被忽略的值。

schema 用例以 schema builder 生成第一项并序列化得到合法 envelope，再添加非法字段，避免手写 DataType wire 表示。schema 测试只在 schema feature 下启用；整个现有测试目标由 json feature 控制。通用 JSON 预算使用默认值，短小负载不会先耗尽它们。

JSON helper 会先构造有界 unique-key 源树，再执行 seed。因此该测试保护的是“领域 value 不被解码”的顺序，不能据此声称没有进行通用 JSON 解析、没有临时树分配或证明流式零分配。

生产实现现已满足测试预期，新增回归应直接通过，不为制造红灯故意修改生产逻辑；也不运行临时生产代码变异。若实际失败，应先定位数据、feature、依赖来源或真实合同差异，不凭计划假设正确。

## 兼容性与下游

不需要破坏兼容性。公开类型、读取行为、错误分类和 wire 表示保持原样。rs-task 当前使用 Metadata 及有界编码，rs-event-bus-redis fixture 的相关集成也无需迁移；本方案不修改它们、不执行 downstream all-features。

本地联合开发如需覆盖来源，可由开发者自行选择显式 Cargo patch；它不能成为独立检出验收前提。本方案不创建这种覆盖。

## 验收、风险与交接

成功条件：四条依赖保留版本及 feature 契约；两个锁文件在隔离环境接受 --locked；四包来源为注册表；两个公开边界回归按上述三步断言通过；最终隔离快照运行当前 crate 既有 CI 成功；最终差异局限于四条依赖、必要锁文件变化和指定测试文件，且用户原有修改保留。

主要风险是注册表与本地候选代码差异、锁文件无关升级、隔离配置未清除本地覆盖。各项分别通过来源核对、lock diff 和受控验收环境验证。网络、工具安装和基础设施故障要与代码失败区分；验证受阻不能声称全部通过。任何回退仅撤销本次产生的修改，不整体 reset 或 restore 用户文件。
